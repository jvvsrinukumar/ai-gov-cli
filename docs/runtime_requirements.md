# Hook Runtime Requirements

**Version:** 17.3.1

All bash hook scripts generated by ai-gov (both Claude Code hooks in `.claude/hooks/` and git hooks in `.claude/git-hooks/` or `.kiro/git-hooks/`) need a JSON runtime to read their config from `config.json`. This document explains what runtimes are supported, how the fallback works, and what to do when neither is available.

---

## The two runtimes

### python3 (preferred)

python3 is the preferred runtime because it is pre-installed on every platform that runs Claude Code:

| Platform | python3 availability |
|----------|---------------------|
| macOS 12+ | Built-in — no install needed |
| macOS 11 and earlier | Built-in via Xcode tools (`xcode-select --install`) |
| Ubuntu 20.04+ | Installed by default |
| Debian 11+ | Installed by default |
| Fedora / RHEL 8+ | Installed by default |
| Windows + WSL2 | Available in the WSL distro (Ubuntu default) |
| Windows native (Git Bash) | Requires install: `winget install Python.Python.3` |
| GitHub Actions (ubuntu-latest) | Pre-installed |
| Docker (node:18) | Not included — `apt install python3` |

### jq (accepted alternative)

jq is the original requirement and still fully supported as a fallback when python3 is unavailable:

```bash
# macOS
brew install jq

# Ubuntu / Debian
sudo apt install jq

# Alpine (Docker)
apk add jq

# Windows (winget)
winget install jqlang.jq
```

---

## How the fallback works

Every generated hook uses this pattern:

```bash
# Claude Code hooks (.claude/hooks/) — _json() helper
_json() {
    local key="$1"
    if command -v jq &>/dev/null; then
        printf '%s' "$INPUT" | jq -r "${key} // empty" 2>/dev/null || true
    elif command -v python3 &>/dev/null; then
        printf '%s' "$INPUT" | python3 -c "
import sys,json
key=sys.argv[1].lstrip('.')
try:
    d=json.load(sys.stdin)
    for p in key.split('.'):
        d=d.get(p) if isinstance(d,dict) else ''
    print(d or '')
except: print('')
" "$key" 2>/dev/null || true
    else
        echo "  ⚠️  ai-gov hook skipped: install jq or python3 to enable governance checks" >&2
    fi
}
```

```bash
# Git hooks (.claude/git-hooks/) — cfg() function
cfg() {
    local expr="$1"
    if command -v jq &>/dev/null; then
        jq -r "${expr}" "$CONFIG" 2>/dev/null || echo "true"
    elif command -v python3 &>/dev/null; then
        python3 -c "
import json,sys,re
try:
    with open(sys.argv[1]) as f: c=json.load(f)
    keys=re.findall(r'[a-zA-Z0-9_-]+', sys.argv[2].split('//')[0])
    v=c
    for k in keys: v=v.get(k) if isinstance(v,dict) else None
    print('true' if v is True else ('false' if v is False else (str(v) if v is not None else 'true')))
except: print('true')
" "$CONFIG" "$expr" 2>/dev/null || echo "true"
    else
        echo "true"
    fi
}
```

**Order of preference:** jq → python3 → warning + graceful skip

## What happens when neither is installed

Claude Code hooks print a warning to stderr and exit 0. The developer sees:

```
  ⚠️  ai-gov hook skipped: install jq or python3 to enable governance checks
```

Git hooks default all `cfg()` calls to `"true"` (i.e., all checks enabled with default thresholds) and run with hardcoded defaults. This means git hooks still work — they just cannot read team-specific thresholds from `config.json`.

**Neither runtime = governance not enforced** (for Claude Code hooks) or **using defaults** (for git hooks). Run `ai-gov doctor` to see a clear diagnostic.

## Platform-specific notes

### macOS

python3 is available as a system binary on macOS 12.3+. On older macOS, it may require:

```bash
xcode-select --install
```

Or install via Homebrew:

```bash
brew install python3
```

Governance hooks work out of the box on macOS without any additional setup.

### Linux / Ubuntu

python3 is the default on Ubuntu 20.04+. For minimal Docker containers:

```dockerfile
# Node.js base image + python3
FROM node:18-alpine
RUN apk add --no-cache python3
```

```dockerfile
# Or debian-based
FROM node:18
RUN apt-get update && apt-get install -y python3 --no-install-recommends
```

### Windows (native — Git Bash)

Install python3:

```powershell
winget install Python.Python.3
```

Or install jq:

```powershell
winget install jqlang.jq
```

Then verify in Git Bash:

```bash
python3 --version
# or
jq --version
```

The `chmod +x` calls for hook scripts are silently ignored on Windows — this is safe and expected.

### Windows (WSL2)

WSL2 with Ubuntu is the recommended environment for Windows users. python3 is pre-installed in the Ubuntu WSL distro.

```bash
# Inside WSL2 Ubuntu
python3 --version  # should already work
```

### GitHub Actions / GitLab CI

python3 is available on all standard runners:

```yaml
# GitHub Actions — no extra step needed on ubuntu-latest
- name: Run governance check
  run: npx ai-gov pr-check
```

```yaml
# GitLab CI — python3 available on standard images
governance-check:
  image: node:18
  script:
    - npx ai-gov pr-check
```

For minimal Docker images, add `python3` before the governance step.

## Docker best practices

For teams running governance checks in CI containers:

```dockerfile
# Recommended: use an image that already has python3
FROM node:18        # debian-based — has python3
FROM node:18-slim   # debian-based — has python3 (slim)

# Avoid (no python3 by default):
FROM node:18-alpine  # add manually: RUN apk add python3
```

Test your container:

```bash
docker run --rm node:18 python3 --version
# should print: Python 3.x.x
```

## Why python3 was chosen over other options

| Option | Availability | Why not chosen as primary |
|--------|-------------|--------------------------|
| `jq` | Requires explicit install on every platform | Good, but not pre-installed anywhere |
| `python3` | Pre-installed on macOS + all major Linux | **Chosen as primary** |
| `node` | Always available (ai-gov runs on node) | Bash cannot easily call node inline without temp files |
| `awk` / `sed` | Always available | JSON parsing with awk is error-prone and unmaintainable |
| `perl` | Available on most systems | Less universally available than python3 on modern systems |

The dual runtime (jq first, python3 fallback) gives teams flexibility: jq-heavy shops can keep using jq, and everyone else gets python3 coverage with zero setup.
