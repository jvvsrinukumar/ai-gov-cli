Steering Files
.claude/steering/  ·  .kiro/steering/
ALWAYS LOADED
constitution.md md
Hard rules, architecture invariants, high-risk files. Also: project context (domain, app description) and data security rules (PHI/PII/general + stack-specific).
priority-1security
architecture.md md
Layer flow, patterns, API docs, external service boundaries, data layer patterns, naming conventions by layer and directory.
layersnaming
coding-standards.md md
Naming rules, type naming, state pattern, error handling, file size limits, import order, and stack-specific testing conventions (MockK/Jest/RTL/pytest/JUnit).
conventionstesting
workflow.md md
New feature / edit / bug fix / refactor / hotfix flows, layer build order, commands table. Also contains: AI usage policy (prerequisites, forbidden actions) and spec-first workflow (gates, STOP rules).
processpolicy
developer-reference.md md
Feature README requirements and template. Prompt templates for each task type. Task size and time estimate markers ([~1h], [S/M/L]) used by /jira command.
referencejira
system-context.md md
Kiro only · Manual inclusion · Conditional. Auto-generated index of .kiro/notes/ files using #[[file:...]] references. Only created when notes directory has .md files.
kiro-onlyconditional

Slash Commands
.claude/commands/  ·  triggered by typing /command-name
CLAUDE CODE ONLY
new-feature.md
Spec-first 3-gate workflow. Knowledge preamble → Gate 1 requirements → Gate 2 design → Gate 3 tasks → implementation. Silent knowledge capture after Gate 1.
3 gatescaptures
edit-feature.md
Diff-based edit of existing feature. Shows <!-- NEW --> and <!-- CHANGED --> markers. Silent capture only for changed items.
diffcaptures
fix.md
Bug fix with diagnostic gate. Reads knowledge before diagnosing. Selective capture: only when root cause is a misunderstood requirement or unenforced constraint.
plan modeselective
hotfix.md
Emergency production fix. Faster than /fix — same knowledge preamble, no spec written. Deploy first, ticket after.
urgent
refactor.md
Reads knowledge/tech for existing layer structure. Approval gate if >10 files. No silent capture — refactors change structure, not business rules.
plan mode
explore.md
Read-only codebase exploration. Reads knowledge preamble first. No writes, no spec, no gates — pure discovery.
read-only
audit.md
Architecture compliance + code quality + Knowledge Health check. Reports [STALE] and [UNVERIFIABLE] knowledge entries. Release gate.
health checkdrift
assess.md
Technical debt + risk assessment. Business Pressure rubric, ASSUMPTIONS block, no human-input gates — fully automated.
automated
tech-knowledge.md
Writes knowledge/tech-[scope].md. Stack Primer, Layer Map, First-Run Guide, Env Vars, DB connection (any SQL client), Daily Commands, Stack Notes, API Access, Logging. Offers sql export.
writes kbSTEP 3.5
product-knowledge.md
Writes knowledge/product-[scope].md. User flows, domain objects, permissions, business states, API endpoint catalog, contribution workflow.
writes kb
knowledge.md
Read-only viewer for knowledge/ files. Zero writes, zero scanning. Safe for all developers. /knowledge auth shows tech-auth.md + product-auth.md.
read-only
detect-conflicts.md
Cross-feature conflict detection. Reads all product-*.md files, surfaces contradicting business rules, writes knowledge/conflicts/ decision inbox.
team lead
backlog.md
Story estimation and backlog breakdown. Stack-specific user story templates, sizing with [S/M/L], no human-input gates.
planning
jira.md
Jira worklog logging, ticket sync, status transitions. Reads [~1h] estimate markers from developer-reference.md. Post-task nudge via post-task-checklist.
jira

Hooks — preToolUse
.kiro/hooks/  ·  fires before every tool use
SAFETY GATES
block-dangerous-commands
Intercepts shell tool calls. Blocks rm -rf, drop table, git push --force, format/wipe commands. Zero cost in normal operation — essential safety net.
shell guardcritical
protect-files
Blocks writes to steering files, governance config, git hooks, and scanned high-risk files. Prevents AI from overwriting the governance setup itself.
write guardcritical
pre-write-secrets-gate
Scans the content about to be written for credential patterns (API keys, tokens, passwords). Blocks the write if detected — before any damage is done.
secretscritical
spec-first-gate
Blocks code generation if no Gate 3-approved spec exists. Only active when specFirstEnabled=true (project has existing spec history). Enforces spec-before-code.
conditionalspec-first
✨
Hooks — postToolUse
.kiro/hooks/  ·  fires after each file write
AUTO QUALITY
format-code
Runs the stack's formatter (prettier, ruff format, dart format, spotless) on every file written. Auto-formats without developer action. Only generated when a formatter is detected.
per-fileconditional

Hooks — fileEdited
.kiro/hooks/  ·  fires when a matching file is saved
SECURITY SCAN
check-secrets
Post-write scan for accidentally included credentials, tokens, or PII in any source file. Complements pre-write-secrets-gate — catches edge cases that bypass the pre-write check.
secretssecurity
💬
Hooks — promptSubmit
.kiro/hooks/  ·  fires when user submits a message
SESSION CONTEXT
session-continuity
Injects project context at the start of each Kiro session. Kiro workflows are fresh askAgent sessions — this hook reads disk state so the agent knows what's in progress without conversation history.
contextkiro-essential
✅
Hooks — postTaskExecution
.kiro/hooks/  ·  fires once per task completion
PER-TASK CHECKS
analyze-code
Runs the stack linter (eslint, ruff check, dart analyze, checkstyle) ONCE when the task completes — not after every file write. One clean lint pass over everything written.
per-taskconditional
post-task-checklist
After each spec task: verifies architecture compliance, no skipped layers, tests written, file size, tasks.md updated ([ ] → [x]). Reminds to run Jira sync if .jira metadata exists.
checklistjira

Hooks — userTriggered
.kiro/hooks/  ·  triggered from Kiro workflow panel
KIRO WORKFLOWS · 14

Each workflow runs as a fresh askAgent session. The hook's prompt is fully self-contained — includes knowledge preamble, instructions, and output format. Both Claude Code (/command) and Kiro (workflow panel) produce identical output to the same knowledge/ and specs/ directories.

workflow-new-feature
Kiro equivalent of /new-feature. STEP 0 reads disk state. 3-gate: requirements → design → tasks. Silent capture after Gate 1. Spec written to .kiro/specs/.
3 gatescaptures
workflow-edit-feature
Kiro equivalent of /edit-feature. Diff view with markers. Selective capture for NEW/CHANGED items only.
diff
workflow-fix
Bug fix with diagnostic gate. Selective knowledge capture — blocklist prevents trivial fixes from polluting product knowledge.
selective
workflow-hotfix
Emergency production fix. Same capture logic as workflow-fix.
workflow-refactor
Reads tech knowledge for layer context. Approval gate on large changes. No capture.
workflow-explore
Read-only codebase exploration with knowledge preamble. Zero writes.
workflow-audit
Architecture + Knowledge Health check. Reports drift and unverifiable entries. Release gate.
drift
workflow-assess
Technical debt + risk assessment. No gates — fully automated output.
workflow-backlog
Story breakdown and estimation. Stack-specific story templates.
workflow-plan-phases
Phase planning for large features — breaks down scope into ordered phases.
workflow-tech-knowledge
Kiro equivalent of /tech-knowledge. STEP 0 asks scope. STEP 1.5 scans .env.example, manifest, DB config (backend). Writes knowledge/tech-[slug].md. Offers sql export.
writes kb
workflow-product-knowledge
Kiro equivalent of /product-knowledge. Writes knowledge/product-[slug].md. API catalog + contribution workflow for backend stacks.
writes kb
workflow-detect-conflicts
Cross-feature conflict detection. STEP 0 asks scope. Writes knowledge/conflicts/ decision inbox.
workflow-jira-sync
Jira worklog, ticket sync, status transitions. Reads [~xh] estimate markers. Workspace version scans all project specs for cross-project story assembly.
jira

Claude Code Hooks
.claude/hooks/  ·  shell scripts, wired via settings.json
CLAUDE CODE ONLY

Trigger routing is configured in .claude/settings.json. PreToolUse fires before Edit/Write/Bash. PostToolUse fires after Edit/Write. Stop fires when Claude finishes a turn.

protect-files.sh PreToolUse
Blocks writes to steering, governance config, git hooks, and high-risk files.
check-secrets.sh PreToolUse
Scans staged content for credential patterns before write.
block-dangerous-commands.sh PreToolUse
Blocks destructive shell commands.
check-spec-exists.sh PreToolUse
Blocks code generation without a spec. Only when specFirstEnabled=true.
session-continuity.sh PreToolUse
Injects project context at session start.
format-code.sh PostToolUse
Auto-formats every written file using the stack's formatter.
analyze-code.sh Stop
Runs linter once per Claude turn (Stop hook) — not per file write.
post-task-checklist.sh Stop
Architecture compliance, tests, file size, spec updated, Jira reminder.

Git Hooks
.git/hooks/  ·  fire at git commit time
COMMIT GUARDS
pre-commit
Wrapper that runs all .claude/git-hooks/checks/. Runs: knowledge-confirmed.sh (guards [CONFIRMED] removal), secrets check, file-size check. Never runs with --no-verify unless explicitly asked.
pre-commitknowledge guard
commit-msg
Enforces commit message format — must include ticket prefix or conventional commit type. Blocks commit if format is violated.
commit-msg
knowledge-confirmed.sh
Blocks removal of any [CONFIRMED] entry from knowledge/*.md files. [CONFIRMED] entries are human-verified — they cannot be silently deleted by AI. Bypass: AI_GOV_KNOWLEDGE_OVERRIDE=1 git commit
knowledgebypassable

Knowledge Hub
knowledge/  ·  committed to git · shared between Claude Code and Kiro
AI MEMORY

Written by /tech-knowledge and /product-knowledge. Read automatically by every developer command via the knowledge preamble. Grows as a byproduct of Gate 1 approvals. Both agents share the same directory.

tech-[scope].md md
HOW the codebase is built. Stack Primer, Layer Map, First-Run Guide, Env Variables, DB connection, Daily Commands, API Access, Logging. Written by /tech-knowledge.
[INFERRED]backend+
product-[scope].md md
WHAT the product does. User flows, domain objects, permissions, business states, API endpoint catalog. Written by /product-knowledge, then grown by Gate 1 silent capture ([CONFIRMED] entries).
[CONFIRMED]auto-grows
db-schema-discovery.sql sql
15 ready-to-run schema discovery queries for the detected DB engine. Project-aware: header injects ORM name, migration table (typeorm_migrations, alembic_version, etc.). Run in any SQL client.
optionalcommitted
conflicts/[a]-vs-[b].md md
Cross-feature conflict decision inbox. Written by /detect-conflicts. Team lead resolves open conflicts by editing the file ([ ] Unresolved → [x] Resolved — decision). Re-raised unless resolved.
team lead
